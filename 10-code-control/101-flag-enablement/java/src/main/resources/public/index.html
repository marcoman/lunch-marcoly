Context → variation → response

Build the evaluation context, evaluate the string flag with a safe default, then shape the served value for the grid.

Trimmed from HostOs.java and FlagEvaluator.java.

// Context: user key plus private hostOs for targeting.
LDContext context = LDContext.builder(username)
    .set("hostOs", HOST_OS)
    .privateAttributes("hostOs")
    .build();

// Evaluate each flag. The last argument is the safe default.
String highlightRaw = client.stringVariation(
    "enable-grid-selection-highlight",
    context,
    "none"
);
boolean highlight = !HighlightStyle.isHighlightOff(highlightRaw);
String servedColor = highlight ? highlightRaw : null;
boolean contextHighlight = client.boolVariation(
    HighlightStyle.FLAG_CONTEXT, context, false
);
boolean showCount = client.boolVariation(
    HighlightStyle.FLAG_COUNT, context, false
);
boolean showOsEmoji = client.boolVariation(
    HostOs.FLAG_OS_EMOJI, context, false
);

// The served values choose highlight, count, and emoji.
HighlightStyle.Style style = HighlightStyle.resolve(
    username, highlight, contextHighlight, servedColor
);
String osEmoji = HostOs.osEmojiFor(HOST_OS, showOsEmoji);
return new FlagValues(
    highlight,
    contextHighlight,
    showCount,
    style.highlightColor(),
    style.cohortLabel(),
    osEmoji
);
What this example is

This example teaches LaunchDarkly feature flags on the grid navigator: a string highlight flag, a boolean color override, move count, and a host OS emoji.

What we show

Log in and move on the grid. Code Example is the server path that builds the context, evaluates enable-grid-selection-highlight, and shapes the served value for the grid.

Color override (app logic)

enable-grid-highlight-color-override is a boolean gate: LaunchDarkly only says on/off. When on, this application looks for human / robot / beta in the login name and chooses the color: human→yellow, robot→red, beta→blue, human+beta→green, robot+beta→purple. Try logging in as human-beta.

Why it matters

You ship the app once and enable features in LaunchDarkly—so product and ops can change behavior without a redeploy. Keywords: string variations, boolean variations, contexts, private attributes.
