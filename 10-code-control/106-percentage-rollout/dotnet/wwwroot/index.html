Why it sticks

LaunchDarkly hashes flag + context kind + context key into one of 100,000 buckets. Same inputs, same bucket.

Try several usernames. Two names can legitimately land in the same side.

Context → variation → response

Build a user context from the username, ask for the variation detail, then return the value, variation index, and reason. The app never computes a percent.

Trimmed from dotnet/Rollout.cs, served by dotnet/Program.cs.

// Context: the username is the user key LaunchDarkly buckets.
var ldContext = new { kind = "user", key = username, name = username };
var context = Context.Builder(username).Kind("user").Name(username).Build();

// Evaluation: StringVariationDetail returns the value plus why it was served.
var detail = _client.StringVariationDetail(FlagKey, context, DefaultValue);
var raw = detail.Value;
var value = Valid.Contains(raw) ? raw : DefaultValue;
var index = detail.VariationIndex;

// Response: served value, variation index, and reason for the drawer.
return new
{
    flagKey = FlagKey,
    flagValue = value,
    highlightColor = value,
    variationIndex = index < 0 ? (int?)null : index,
    reason = ReasonPayload(detail.Reason),
    ldContext,
};
What this teaches

A percentage rollout serves green to a fixed share of usernames and none to the rest. LaunchDarkly buckets the user context key. The same username keeps its variation until someone edits the default-rule weights.

The Rollout tab already shows the context that was sent and the variation that came back.

Start a percentage rollout

Open the flag and set the default rule to a percentage rollout. Then come back and try several usernames.

Open enable-grid-selection-highlight-pct targeting

The link appears when LD_PROJECT_KEY and LD_ENVIRONMENT_KEY are set. Restart the server after you export them. For this lab the page is https://app.launchdarkly.com/projects/lunch-marcoly/flags/enable-grid-selection-highlight-pct/targeting?env=production&selected-env=production.

  1. Turn the flag on.
  2. Edit the default rule and choose a percentage rollout.
  3. Give green a share and none the rest. The two shares add up to 100. This lab starts at 30% green / 70% none.
  4. Bucket by the user context key. That key is the username on the grid.
  5. Save the targeting.
  6. Return here. Evaluate a few usernames. Open an older name to see that its variation stayed put.

rest/set-rollout-percent.sh writes those weights immediately. rest/get-rollout.sh prints the weights that are saved.
