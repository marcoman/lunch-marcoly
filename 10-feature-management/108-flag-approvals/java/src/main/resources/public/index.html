About

The number of moves is ordinary application state. It increases when you move on the grid. One boolean flag, show-navigation-move-count-approval, decides whether the Count row is visible. Off hides it. On shows it.

Turning that flag on is a targeting change. This lab sends the change through an approval so the request, the review, and the apply stay separate.

Request approval asks LaunchDarkly to create a request whose only instruction is turnFlagOn. The request is named Turn on the move count plus a counter kept in this example, so each one is distinct in the Approvals list. Reset leaves that counter where it is. The review starts pending, and Apply on this page stays disabled. This page does not approve the request. A person does that in LaunchDarkly. Open in LaunchDarkly goes straight to the request. The Approvals dashboard only lists requests that name you as a reviewer, and this request names none, so the dashboard hides it until you clear that filter.

The page polls. When LaunchDarkly reports the review as approved, and the change is still unapplied, Apply enables. Apply carries out the instruction. The server SDK evaluates the flag again. A true variation shows Count, including moves made while the row was hidden.

The trace on the Approval tab records those steps and labels where each one happened: Lab UI for a click here, Lab API for this server, and LaunchDarkly for the approval service or the flag evaluation. Repeated polls stay on one line until the state changes.

Reset deletes the approval requests for this flag and turns the flag off with turnFlagOff, then clears the count and returns the marker to the center. The lab is ready to run again.
