What each guardrail watches

Latency is the lever, and only a RULE_MATCH green username is reported at the slider. Every other result is reported at 50 ms. Error rate and movement stay in the normal range, so a rollback has one cause. The slider reports a number. It does not delay the move or change the flag.

Violation
Grid navigation latency (grid-nav-latency). Milliseconds the slider reports for one move. Lower is better. Above 200 ms crosses the guardrail.

Normal
Grid highlight error rate (grid-highlight-error-rate). One event would mean the wrong highlight color. This page sends none, so the rate stays at 0%.

Normal
Grid navigation movement (grid-nav-movement). Each move sends 1 navigation. Higher is better, and that count stays at or above the guardrail of one.

What this teaches

One environment release moves api-guarded-grid-highlight from none to green. The call includes three metrics, so the release kind is guarded. The stages are 10% and 20% for two minutes each, then 30% and 50% for one minute each. A guarded release stops at 50% and keeps a control group.

The Guardrails tab names the three metrics. The Release tab starts the release, samples usernames, and traces flag changes, evaluations, percent changes, and rollbacks.

Start the release
  1. Log in once, so the flag has a recent user evaluation.
  2. Click Start guarded release. That creates the flag and the three metrics if they are missing, then POSTs the release.
  3. Leave the slider at 50 ms, or raise it above 200 ms and turn on Report once per second during the first two stages.
  4. Click Try next to sample the next username. The list shows the variation and the reason. The tally counts green against none.
  5. The status line says Monitoring, then Rolled back to none if a guardrail regresses.
  6. Click Stop to roll back early. Click Reset to turn the flag off and remove the phase rule.
