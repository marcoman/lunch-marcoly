Why it moves once

LaunchDarkly buckets the user context key. As the step percentage rises, a key can move from none to green once. After it receives green, it stays green for this release.

What this teaches

One environment release moves api-progressive-grid-highlight from none to green. The call omits metrics, so the release kind is progressive. Five steps serve 10%, 20%, 40%, 60%, then 100%. Each step lasts one minute.

The release targets a rule. The rule's clause is context kind user, attribute kind, operator in, value user. The default rule stays none until the release completes, then LaunchDarkly removes the rule and serves green from the default rule.

The Release tab already shows the context that was sent and the variation that came back.

Start the release
  1. Run rest/create-flag.sh. The flag is off.
  2. Start this page and log in once, so the flag has a recent user evaluation.
  3. Click Start progressive release. That POST starts the release. rest/start-progressive-release.sh sends the same body.
  4. Return here. The step percent climbs. Elapsed time starts when this page notices the step and resets on the next one. The release poll is every 5 seconds, so the clock starts a little after LaunchDarkly moves. Try the next username to sample the split.
  5. Click Stop to roll the phase back to none. rest/stop-progressive-release.sh forward serves green now instead.
  6. Click Reset to turn the flag off. Every context receives none until the next start.
